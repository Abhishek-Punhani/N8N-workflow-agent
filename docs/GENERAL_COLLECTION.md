# General web collection

The running service accepts prompts with no URL, one URL, or multiple HTTPS URLs. Collection uses the configured LLM provider consistently; changing providers is an explicit environment setting. It does not silently switch models.

## Start and test

Use Node 22.12+ or Node 24 for local commands. Docker supplies Node 22 and Chromium.

Set `SEARCH_SECRET` to an independent random value in `.env` (generate it with `openssl rand -hex 32`). It protects the search service independently of n8n and the workspace API.

```sh
docker compose up -d --build --wait
docker compose ps
curl http://localhost:3000/health
curl http://localhost:3000/ready
```

Open http://localhost and sign in using your `.env` workspace access key (`PLATFORM_API_TOKEN`). Try:

> Find 3 TV retailers in Pune, India. Return name, address and publicly listed business phone as fields named name, address, phone. Collect evidence from multiple public sources.

> From https://fakestoreapi.com/products extract title, price and category. Return JSON.

> From https://books.toscrape.com/ collect 3 books with title and price. Return JSON.

These are live-web tasks: availability, source restrictions, evidence coverage and provider quotas can change their results. A completed partial dataset means some qualified records were collected; the coverage panel shows the shortfall. No records passing evidence and field validation produces a failed run with a source report.

Inspect a record to see field evidence, retrieval time and the source page. Download CSV or JSON as before. Numeric extraction confidence is deliberately unset because the service has no calibrated probability model.

## Search configuration

Compose provides a private SearXNG service and enables Google, Bing, Brave and DuckDuckGo engines. Upstream search engines can block or throttle a self-hosted instance. Search results are navigation hints; their snippets are not accepted as final dataset evidence. There is no automatic switch to another provider.

Optional API connectors:

```dotenv
SEARCH_PROVIDER=tavily
SEARCH_API_KEY=your_key
```

Or set `SEARCH_PROVIDER=brave` with its API key. For an externally hosted SearXNG instance, set `SEARCH_PROVIDER=searxng` and `SEARCH_BASE_URL` to that instance. These are operator-configured connector settings, not URLs generated by the model.

## Collection limits

| Variable | Default | Meaning |
| --- | --- | --- |
| `LIMIT_WEB_PAGES` | 30 | Target pages attempted per run, across all sites |
| `LIMIT_COLLECTION_RECORDS` | 500 | Accepted record ceiling |
| `LIMIT_COLLECTION_MODEL_CALLS` | 40 | Collection planning/extraction calls; intake is separate |
| `TIMEOUT_COLLECTION_MS` | 300000 | Collection deadline |
| `COLLECTION_BROWSER_ENABLED` | true | Allow rendering pages needing JavaScript |

Existing `.env` values override defaults. HTTP acquisition caps individual responses, follows at most five redirects and pins DNS to public IPv4. It rejects private networks, embedded URL credentials and non-HTTPS target URLs. Browser acquisition runs in a fresh context with service workers and WebSockets blocked; subrequests use the same public-network transport. Rendering is bounded by time, request count and content size. It supports read-only GET resources, not arbitrary form submissions or authenticated browsing.

The frontier follows model-selected observed links with a depth limit of four. Relevant passages are selected across each page to keep model requests bounded. Extraction therefore does not certify exhaustive coverage. Robots exclusions are respected. Sources requiring login or human verification are reported, and other sources remain eligible for collection.

## Durable progress and retries

The service saves its frontier, visited URLs, partial entities and evidence in the job artifacts after each page. Public execution responses expose collection progress and source outcomes without exposing internal artifacts.

`POST /executions/{id}/retry` creates a new execution for a finished run. It retains the objective/evidence and resumes the saved frontier with a fresh budget. If the frontier was exhausted, it retries failed sources (or revisits prior pages). The API uses the same workspace authentication as other operations. It never resumes a running job concurrently.

Worker interruption remains an explicit failed execution after stale-job reconciliation; collection is resumed through retry rather than silently replaying n8n deployments.

## Implementation boundaries

Source discovery, HTTP/browser acquisition and evidence extraction execute in the platform collection worker. n8n runs the vetted dataset workflow against the acquired records, with structural checks, sandbox execution, output validation, provenance, persistence and export. This release does not claim that n8n's pass-through nodes themselves browse the web.

Only literal supported values and conservative formatting normalization are accepted. Business address fields must contain more than a city alone. Entities with conflicting collected values are excluded pending reconciliation. Cross-page enrichment merges evidence only when the selected identity fields match; missing identity or differently formatted addresses can limit merging. Literal evidence proves that a source published a value; it does not independently establish the source's truthfulness or that a phone number is active or direct rather than a directory relay.

Automatic CAPTCHA solving, interactive human takeover, authenticated site connectors and full browser action planning are not implemented. The browser renders pages and the collector follows observed URLs; it does not perform arbitrary clicks, searches inside forms or account actions. These limitations appear as source failures or partial coverage, rather than synthetic records.

## Checks

```sh
npm run build
npm run lint -- --quiet
npm test
cd dashboard
npm run build
npm test
```

From the repository root, use `E2E_BASE_URL=http://localhost npm run test:stack` for the live API/n8n/persistence/export test and `E2E_BASE_URL=http://localhost npm run test:browser` for browser UI tests. Provider/API usage in live tests consumes the configured account's quota.

`npm run test:collection` runs the no-URL TV-retailer case and writes the actual coverage and records to `reports/general-collection.json`. Override `E2E_PROMPT` to test another objective.
